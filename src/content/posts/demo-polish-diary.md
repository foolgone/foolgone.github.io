演示站被人说了一句「一眼 AI 生成」。这句话不刺耳，但很准确：蓝色主色、圆角卡片、渐变登录页、Inter 字体、彩色胶囊标签——每个元素都合理，合在一起就是模板。

于是这轮做了三件事：把视觉重做一遍，修掉切页时那一瞬间的黑屏，再为「上传音视频做分析」设计一条尽量少改动的路径。

## 一、视觉：先建立约束，再谈好看

我没有直接换配色，而是先定了几条约束：

- 暖纸底 `#FAF8F3`、墨色 `#17160F`、朱砂 `#C8452A` 作为唯一强调色；
- 标题用衬线，标签和数字用等宽；
- 方角、1px 细线、几乎不用阴影；
- 用留白和分割线建立层次，而不是靠卡片堆叠。

这组约束落到 Tailwind Token 后，整站的气质就变了：侧栏改成通栏墨色，页头只留面包屑和数据源选择器；每个页面统一成「编号 / 眉题 / 衬线大标题」；Dashboard 的统计卡不再用图标色块，而是细线顶栏 + 大号衬线数字；图表换成环形饼图、点状网格，去掉单序列的冗余图例；登录页改成左右分屏，左边是一句主张，右边才是表单。

改动最大的其实不是颜色，而是**删掉了那些「看起来像设计」的装饰**：渐变、阴影、彩色胶囊、居中大卡片。删完之后，页面反而更像一个有人做过取舍的产品。

顺带修了几个之前没注意的细节：数据源卡片标题改衬线、元信息改等宽；用户菜单头像从彩色圆片改成方框字母；零数据图表显示空态而不是一条贴底的 0 值红线。

## 二、闪屏：一个边界放错位置的问题

切左侧栏目时会闪一下，像黑屏，又像加载。用 ego 浏览器加 CDP 限速复现后，时间线很清楚：

```text
app      → fallback → app
82039ms    82066ms    83398ms
```

空白持续约 1.3 秒，截图里整个页面只剩左上角一行「加载中...」，**侧栏和页头都没了**。

根因在 `router.jsx`：`Suspense` 包在 `<Routes>` 最外层。页面都是 `React.lazy`，首次进入某个栏目时 chunk 还没下载，fallback 就把整个路由树替换掉——包括 `AppLayout` 里的墨色侧栏。深色侧栏瞬间消失，看起来就是黑屏。

修复分三层：

1. **Suspense 下沉**到 `AppLayout` 的 `<Outlet />` 外，切页时只可能替换内容区，侧栏和页头保持挂载；
2. 给 `BrowserRouter` 开启 `v7_startTransition`，新页面 chunk 加载期间保留旧页面，不再闪 fallback；
3. 空闲时预取全部业务路由 chunk，首次点击通常已经命中缓存。

验证方式不是「看起来不闪了」，而是用 MutationObserver 记录切页过程：连续切换 6 个栏目，`aside` 始终为 `true`，`fallback` 始终为 `false`。

这件事的教训是：**闪屏通常不是动画问题，而是 React 边界放错了位置**。

## 三、音视频：先设计数据流，再写代码

目前上传只支持 CSV / JSON / XLSX / TXT。想做音视频分析，最直接的想法是「加个 accept，然后调 ASR」，但真正难的是：ASR 出来的是一段文本，而现有质量评估需要「用户问 / 客服答」成对的对话。

所以方案选了云 ASR（方案 B），并且优先支持**双声道通话录音**：

```text
上传音视频 → 存对象存储
  → 复用 clean 任务
      PARSING：ffmpeg 抽音轨 / 拆 L/R → 云 ASR
      NORMALIZING：已有 records，跳过清洗 Agent
      VALIDATING：复用 _persist_dialogues 写 cleaned_data
  → evaluate / extract / insight / report 全部复用
```

双声道是关键：左声道是客户、右声道是坐席，分别转写后按时间戳配对，就能得到现有链路认识的 `user_message` / `ai_response`。单声道则降级为一段文本，只适合知识提取和文本洞察，不适合对话质量评估。

这次刻意守住了「非必要不增实体」：

- 0 张新表：转写结果放 `raw_data.raw_content`（JSONB）；
- 0 个新迁移：复用现有字段；
- 0 个新任务类型：转写作为 `clean` 任务的 `PARSING` 阶段；
- 0 个新页面：复用上传弹窗、任务列表和清洗结果抽屉。

代价是 ASR 成本不能进 `llm_calls`（那是 LLM 专用表），只能先写进 `task.result.asr.cost_estimate`。这是一次有意识的取舍：先不为了统计口径去加一张表。

MVP 估算是 4 天：`media_service` 1.5 天、上传与清洗分支 1 天、前端 0.5 天、集成测试与真实样本验收 1 天。

## 四、这轮之后

视觉重构和闪屏修复已经上线（云服务器 + VM），前端 70 个测试文件、331 条用例全绿。音视频目前只有设计，没有代码。

接下来如果继续，优先级大概是：

1. 按设计实现音视频 ASR MVP；
2. 补上洞察页面和统一任务中心——后端接口早就有了，前端还没有入口；
3. 评估结果去重和成本/配额页，让「数字可信」这件事闭环。

这轮最大的感受是：**演示站的完成度，不取决于功能数量，而取决于那些不显眼的边界**。一个 Suspense 放错位置，就能让精心做的界面闪成黑屏；一个「先加个 accept」的冲动，就会让数据模型多出一堆本可以不存在的实体。
