设计不一致往往不是审美问题，而是缺少一套共享的词汇。设计师说「这里轻一点」，工程师听到的是「调低透明度还是换个灰度」——中间那层翻译，就是设计令牌。

## 令牌不是变量

变量只是实现手段。令牌真正的作用是**命名决策**：

```css
:root {
  /* 不是 --gray-3，而是它承担的职责 */
  --text-muted: #6f665c;
  --surface-raised: #fffdfa;
  --border-subtle: #e4ded4;
}
```

`--gray-3` 描述的是它长什么样，`--text-muted` 描述的是它为什么存在。前者在换主题时会失效，后者不会。

## 三层结构

我在项目里通常分三层，越往下越稳定：

| 层级 | 示例 | 谁在用 |
| --- | --- | --- |
| 原始值 | `--palette-warm-50` | 只被下一层引用 |
| 语义 | `--surface`, `--text` | 组件与页面 |
| 组件 | `--button-bg` | 单个组件内部 |

只有语义层是对外承诺。原始值可以随时重排，组件令牌可以跟着组件一起删掉。

## 间距用比例，不用数字

间距不要出现 `13px`、`27px` 这种孤立值。定一条基准线，其他值都从它派生：

```css
:root {
  --space-1: 0.25rem;
  --space-2: 0.5rem;
  --space-3: 0.75rem;
  --space-4: 1rem;
  --space-6: 1.5rem;
  --space-8: 2rem;
}
```

刚开始会觉得受限，两周之后你会发现页面自然对齐了，因为所有间距本来就来自同一组数字。

## 暗色模式是一次压力测试

如果令牌分层做对了，暗色模式只需要重新定义语义层：

```css
[data-theme='dark'] {
  --text: #ece6dd;
  --surface: #1a1714;
  --border-subtle: #2a2521;
}
```

如果做错了，你会发现自己在一堆组件里到处写 `if dark`。这时候不要急着加特例，先回头看看哪一层泄漏了。

> 一套好的令牌，应该让人在写新页面时不需要问「这个颜色用哪个」，因为答案只有一个。
